# DaQauntum Roadmap

## Current — v0.4.0 Presence + Guided Demo

A persistent local-first intelligence that can be launched, chatted with through a configured real model, spoken to, speak back, remember, learn, ingest connected information, observe screen/camera context, passively monitor approved local signals, explicitly discover nearby radios/services, and prepare permission-gated actions.

## v0.4.1 — Device Drivers + Event Reactions

- BLE GATT adapter framework;
- serial sensor adapter SDK;
- MQTT subscriptions / retained-state cache;
- configurable presence rules;
- notification queue for important ambient changes;
- richer Home Assistant sensor-state ingestion;
- hardware capability registry.

## v0.4.2 — Secure Mobile Client

- authenticated device enrollment;
- mobile chat/call client;
- remote approvals;
- push notifications;
- camera/file sharing;
- secure Tailscale-first remote workflow.

## v0.4.3 — DaQauntum Native Model Lab

- curated train/validation/test corpus;
- LoRA / QLoRA pipeline for an open-weight base model;
- teaching, physics, coding, tool-use and safety evaluations;
- model registry and candidate promotion policy;
- no self-deployment without evaluation + human approval.

## v0.5.x — Multi-Atom Universe

- authenticated peer atoms;
- explicit shared molecules/workspaces;
- selective knowledge exchange;
- capability/resource negotiation;
- no implicit sharing of private memory.

## v1.0 target

A secure, persistent, multimodal, device-aware DaQauntum service that can converse naturally, maintain durable identity/memory, learn from evidence, operate approved digital/physical tools, and remain understandable and controllable by its user.
