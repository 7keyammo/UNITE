# DaQauntum v0.5.0 — Engineering Report

## What was built

A scientific core for DaQauntum, extending v0.4 rather than replacing it.
Roughly 5,100 lines across `science/` and `physics/`, with 2,700 lines of tests
in ten suites and 83 named test cases, over twelve commits.

Every v0.4 subsystem and test still runs. Nothing was rewritten.

| Layer | Module | What it does |
| --- | --- | --- |
| Units | `science/units.py` | SI dimensional analysis, seven base dimensions, uncertainty in quadrature |
| Domain | `science/models.py` | Experiment, Hypothesis, Measurement, Evidence, Claim, Provenance |
| Events | `science/events.py` | 20 typed event kinds, exempt from bus suppression |
| Storage | `science/store.py` | five tables on the kernel's existing SQLite connection |
| Analysis | `science/analysis/motion.py` | displacement, velocity, acceleration, least squares |
| Facade | `science/core.py` | the one path in, and the refusals that keep it honest |
| Sensors | `science/sensors.py` | backend interface, mock cart, static replay |
| Plots | `science/plots.py` | SVG with no plotting library |
| Backends | `science/backends.py` | research and simulation adapters |
| Validation | `science/validation.py` | fail-closed contradiction checks |
| Reference | `science/reference/cart_motion.py` | the worked experiment |
| Physics | `physics/concepts.py` | 11 quantities, 7 relations with conditions |

Plus eleven `/api/science` routes and `kernel.science` on the existing
composition root.

## The decisions that mattered

**Dependency-free units, verified against Pint rather than provided by it.**
The core computes its own dimensional analysis. `evaluations/units_smoke_test.py`
cross-checks twenty conversions and eight compatibility pairs against Pint where
Pint is installed — worst relative error 5.7e-16, zero mismatches — and where it
is absent the test skips with an explicit note that the conversions are *not*
independently verified. A reference library is used to check the work, never to
do it, and the test does not report a pass it did not earn.

**Scientific events opt out of bus suppression.** The v0.4 bus deduplicates by
design, which is right for a chatty door sensor and wrong for data: two readings
of 1.0 m are two facts. Every scientific event carries a dedupe key unique to
the object it reports, and a test records five identical values and asserts five
stored events. This was the single largest hazard in reusing the existing bus,
and it would have been invisible — an analysis over deduplicated readings gives
a wrong answer that looks entirely normal.

**`evidence_kind` is computed, never stored.** Derived → `CALCULATION`,
simulated provenance → `SIMULATION`, imported → `LITERATURE`, otherwise
`MEASUREMENT`. A stored label can drift from the record it describes; a computed
one cannot.

**The facade refuses rather than accommodates.** `record_measurement` rejects
derived values and `CALCULATED`/`SIMULATED`/`AI` provenance outright.
`interpret()` fixes its own evidence kind, so a model's reading cannot be filed
as a measurement. `make_claim` resolves every cited id. Linking evidence to a
hypothesis never changes its status. Each refusal exists because the permissive
version produces a record that overstates what is known, silently.

**Provenance is rendered onto plot images.** A chart is the part of a record
most likely to be screenshotted and pasted where its metadata does not follow,
so a plot of generated data says so in the picture.

**`OpenScienceBackend` is a documented stub with no network code.** Writing an
adapter against an unverified API produces something that looks finished and
fails unpredictably. In a system whose purpose is separating what is known from
what is guessed, shipping an integration built by guessing would be the sharpest
available contradiction of the product. `search()` raises rather than returning
an empty list, so a failed lookup is never read as "nothing has been published".
The six things that must be verified first are in the code and in
`docs/INTEGRATIONS.md`.

**Validation fails closed.** Unknowns resolve to `UNCERTAIN`, never `PASS`. One
uncertain check makes the whole report uncertain. A validator that passes what
it cannot check certifies whatever it fails to understand — and is blind exactly
where the novel work is.

## Bugs found and fixed

**The falsy zero timestamp.** `Measurement.from_dict` read timestamps as
`data.get("timestamp") or now()`. Since `0.0` is falsy, the first sample of every
run came back from storage stamped with the wall clock. The series then
re-sorted with its first sample last and the displacement came back *negative*.
Nothing about the result looked wrong. Found by a sensor test asserting a
hand-computed value; fixed with an explicit absence check across every stored
time and covered by a named regression test.

**`raw_measurements` counted imported data as measured.** `stats()` defined
"raw" as not-derived-and-not-simulated, so example data imported from a textbook
was reported as a reading of the world. Now counted positively — human or sensor
provenance, not derived — and `list_measurements` gained `readings_only` for the
same reason: excluding known origins silently admits any origin added later.

**A test runner that could not fail.** An earlier suite loop read `$?` after a
pipeline, so it reported `tail`'s exit status rather than Python's and would have
called a failing suite green. It did: two suites were failing for a missing
`websockets` dependency while being reported as passing, and the Phase 5 commit
message claimed 22/22 on that basis. The commit message was amended to state
what was actually verified, and the runner now checks each test directly.

## What is not done

**One real sensor path against real hardware.** The remaining v0.4.1 criterion.
This container has no GPU, no `/dev/snd`, no camera and no sensors, so it cannot
be closed from here and is not claimed. `docs/REAL_HOST_PLAN.md` marks everything
hardware-dependent as BLOCKED rather than assumed working.

**Fourteen commits carry the wrong committer email.** Commits made earlier in
this work used the account email rather than `noreply@anthropic.com`. Everything
from Phase 5 onward is correct. Fixing the earlier ones requires a history
rewrite and a force-push, which is the user's decision to make.

**Statistical depth.** OLS reports r² and a slope standard error. Weighted least
squares, confidence intervals on fit parameters and a proper residual test for
model adequacy are the obvious next step, and the current output is honest about
the limits of what it reports.

**The education layer.** `Depth` exists on experiments and concepts and carries
no content. Generating explanations without checking them against the registry
would produce confident wrong physics, so the field is carried and left empty.

## The line

A calculated value never becomes a reading. A simulation never becomes a
measurement. An AI interpretation never becomes evidence of the world. A
hypothesis never becomes proven. Every test in `evaluations/` that asserts a
refusal is there to keep one of those four true under a future change.
